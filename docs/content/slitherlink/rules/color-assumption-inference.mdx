## What it does

Colors an unknown cell inside or outside when assuming the opposite color on that
cell leads to a contradiction after deterministic propagation.

The visible conclusion is a cell color change (green or yellow). When this rule
fires in the solver, its step in **Reasoning Steps** includes a **View details**
link. Click it to open the **Branch Inspector** and replay the green and yellow
trial branches from the base puzzle through each deterministic step to the
contradiction.

![Branch Inspector replay for a color assumption step](https://cdn.jsdelivr.net/gh/SmilingWayne/picsrepo/20260616172416583.png)

## When it triggers

The rule runs only after every deterministic Slitherlink rule has been applied
to a fixpoint. It then searches color-assumption candidates among cells that are
still uncolored but touch at least one already colored neighbor.

Candidates are grouped into parity components: cells linked by decided edges must
take opposite colors across a line and the same color across a cross. One
representative cell per component is tested, preferring cells with more decided
edges, tighter sector constraints, and more colored neighbors.

For each representative, the solver temporarily colors it green on one branch and
yellow on the other, then runs the full deterministic rule list on each branch
within a rising probe budget (24, 96, 384, then the maximum trial-step cap).
The rule acts when exactly one branch reaches a hard contradiction and the
other does not within the current budget. If both branches contradict, both
remain feasible, or the time or step budget is exhausted, the rule makes no
change.

## Why it works

Inside/outside coloring must stay consistent with every decided edge and with
the single-loop geometry. If assuming one color on a cell forces a hard
contradiction — such as a vertex-degree violation, clue mismatch, sector-mask
conflict, premature loop, disconnected inside region, or a direct color-edge
clash — that color cannot be correct. The surviving assumption is therefore
forced on the real board.

Because parity components already fix opposite colors across decided edges, one
successful test on a component representative decides the color for every cell
in that component.
